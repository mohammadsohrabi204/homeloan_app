# صندوق وام خانگی

اپلیکیشن مدیریت صندوق وام گروهی (قرض‌الحسنه) با قرعه‌کشی ماهانه، پنل مدیریت، پنل کاربری و درگاه پرداخت.

ساخته‌شده با Python و Django.

## چه کاری انجام می‌دهد

هر طرح وام یک گروه از افراد است که هر ماه مبلغ مشخصی می‌پردازند، و هر ماه یکی از آن‌ها به‌قید قرعه کل مبلغ وام را دریافت می‌کند. تا وقتی همهٔ اعضا یک بار برنده نشده‌اند، کسی دوبار برنده نمی‌شود.

امکانات:

| بخش | توضیح |
|---|---|
| طرح‌های وام | مبلغ کل، قسط ماهانه، تعداد دوره، ظرفیت — فقط توسط مدیر تعریف می‌شود |
| رزرو | کاربران عادی فقط می‌توانند جای خالی رزرو کنند |
| اقساط | با شروع طرح، جدول اقساط برای همهٔ اعضا به‌صورت خودکار ساخته می‌شود |
| پرداخت | درگاه آنلاین (زرین‌پال) یا واریز دستی با تأیید مدیر |
| قرعه‌کشی | زمان اعلام‌شده + شمارش معکوس زنده + اعلام برنده |
| شفافیت | هر عضو فهرست اعضای طرح خودش و وضعیت برنده‌شدن را می‌بیند |
| گزارش رویدادها | ثبت غیرقابل‌حذف ورود، ساخت وام، تأیید پرداخت و قرعه‌کشی |
| امنیت | ورود دومرحله‌ای، محدودسازی تلاش ورود، هش Argon2 |

## نقش‌ها و دسترسی‌ها

**مدیر صندوق** (`is_staff = True`)

- تنها کسی که می‌تواند طرح وام بسازد، قیمت و قسط را تعیین کند
- شروع طرح، تأیید پرداخت دستی، زمان‌بندی و اجرای قرعه‌کشی
- دسترسی به پنل مدیریت `/admin/`

**عضو عادی**

- دیدن وام‌های باز و رزرو یک جای خالی
- دیدن اقساط خودش و پرداخت
- دیدن زمان قرعه‌کشی و نتیجه
- **هیچ دسترسی‌ای به پنل مدیریت ندارد**

> یک عضو عادی نمی‌تواند وام بسازد، پرداخت کسی را تأیید کند، یا قرعه‌کشی را اجرا کند. این محدودیت در سطح کد بررسی می‌شود، نه فقط در ظاهر رابط کاربری، و تست خودکار دارد.

## راه‌اندازی سریع

نیازمندی: **Python 3.10 یا بالاتر**

```bash
# ۱) محیط مجازی
python -m venv .venv
source .venv/bin/activate        # ویندوز: .venv\Scripts\activate

# ۲) نصب کتابخانه‌ها
pip install -r requirements.txt

# ۳) فایل تنظیمات
cp .env.example .env
```

حالا فایل `.env` را باز کنید و یک `SECRET_KEY` بسازید:

```bash
python -c "import secrets; print(secrets.token_hex(32))"
```

مقدار خروجی را در `.env` جلوی `SECRET_KEY=` بگذارید. سپس:

```bash
# ۴) ساخت دیتابیس
python manage.py migrate

# ۵) ساخت حساب مدیر
python manage.py createsuperuser

# ۶) اجرا
python manage.py runserver
```

برنامه روی `http://127.0.0.1:8000` بالا می‌آید. پنل مدیریت: `http://127.0.0.1:8000/admin/`

### دادهٔ نمونه (اختیاری)

برای دیدن برنامه با داده‌های آماده:

```bash
python manage.py seed_demo
```

این دستور یک مدیر، پنج عضو و دو طرح وام می‌سازد. رمز همه `Demo!Pass2026` است.

> این دستور فقط وقتی `DJANGO_DEBUG=true` باشد اجرا می‌شود و روی سرور واقعی عمداً خطا می‌دهد.

## راهنمای مدیر

### ۱. ساخت یک طرح وام

پنل مدیریت ← **طرح‌های وام** ← افزودن:

| فیلد | توضیح |
|---|---|
| عنوان | مثلاً «وام جهیزیه — دورهٔ بهار» |
| مبلغ کل وام | مبلغی که برنده دریافت می‌کند |
| قسط ماهانه | مبلغی که هر عضو ماهانه می‌پردازد |
| هزینهٔ خدمات | اختیاری، هزینهٔ اداره صندوق (نه سود) |
| تعداد دوره | هم تعداد اقساط، هم تعداد قرعه‌کشی‌ها |
| ظرفیت | حداکثر تعداد عضو |
| وضعیت | `باز برای رزرو` تا کاربران ببینند، `پیش‌نویس` تا مخفی بماند |

> رابطهٔ منطقی: `قسط ماهانه × ظرفیت` باید تقریباً برابر `مبلغ کل وام` باشد، تا پول جمع‌شدهٔ هر ماه کفاف وام آن ماه را بدهد.

### ۲. شروع طرح

وقتی ظرفیت پر شد: طرح را انتخاب کنید ← اکشن **«شروع طرح‌های انتخاب‌شده و ساخت اقساط»**.

از این لحظه جدول اقساط همهٔ اعضا ساخته می‌شود و در پنل کاربری‌شان نمایان می‌شود.

### ۳. تأیید پرداخت (در حالت واریز دستی)

پنل مدیریت ← **اقساط** ← انتخاب ← اکشن **«تأیید دستی پرداخت‌ها»**.

### ۴. قرعه‌کشی

**الف) اعلام زمان:** پنل مدیریت ← **قرعه‌کشی‌ها** ← افزودن ← طرح، شمارهٔ دوره و زمان را مشخص کنید.

از این لحظه، همهٔ اعضا در صفحهٔ طرح یک **شمارش معکوس زنده** تا آن لحظه می‌بینند.

**ب) اجرا:** در زمان مقرر، قرعه‌کشی را انتخاب کنید ← اکشن **«برگزاری قرعه‌کشی»**.

برنده بلافاصله در پنل همهٔ اعضا نمایش داده می‌شود.

**قوانین واجدشرایط بودن** (به‌صورت خودکار اعمال می‌شود):

1. رزرو باید تأییدشده باشد
2. قسط **همان دوره** باید پرداخت‌شده باشد
3. عضو نباید قبلاً در همین طرح برنده شده باشد

## درگاه پرداخت

در `.env` مقدار `PAYMENT_GATEWAY` را تعیین کنید:

### `manual` — واریز دستی (پیش‌فرض)

بدون نیاز به مرچنت کد. کاربر مبلغ را کارت‌به‌کارت واریز می‌کند و مدیر در پنل تأیید می‌کند. برای صندوق‌های خانوادگی و شروع کار کافی است.

### `zarinpal` — درگاه آنلاین

```env
PAYMENT_GATEWAY=zarinpal
ZARINPAL_MERCHANT_ID=کد-مرچنت-شما
ZARINPAL_SANDBOX=true
```

> `ZARINPAL_SANDBOX=true` یعنی حالت آزمایشی (پول واقعی جابه‌جا نمی‌شود). پیش از انتقال به پول واقعی حتماً چند تراکنش کامل را در حالت آزمایشی تست کنید و مستندات فعلی زرین‌پال را بررسی کنید، چون APIهای درگاه‌های پرداخت گاهی تغییر می‌کنند.

### افزودن درگاه دیگر

فایل `payments/gateways.py` را باز کنید و یک کلاس از `BasePaymentGateway` بسازید که دو متد `request_payment` و `verify_payment` را پیاده‌سازی کند، سپس آن را به تابع `get_gateway()` اضافه کنید. نیازی به تغییر در بقیهٔ برنامه نیست.

## امنیت

موارد پیاده‌سازی‌شده:

- **رمز عبور:** هش Argon2 (برندهٔ مسابقهٔ جهانی هش رمز عبور) — رمز هرگز به‌صورت متن ذخیره نمی‌شود
- **ورود دومرحله‌ای (2FA):** بر پایهٔ TOTP، سازگار با Google Authenticator و Authy
- **محدودسازی تلاش ورود:** جلوگیری از حملهٔ حدس رمز
- **CSRF و XSS:** محافظت داخلی Django روی همهٔ فرم‌ها
- **قرعه‌کشی امن:** استفاده از ماژول `secrets` (مولد تصادفی رمزنگاری‌شده) به‌جای `random` معمولی که قابل پیش‌بینی است
- **اثبات عدم دستکاری:** برای هر قرعه‌کشی، فهرست واجدشرایط‌ها + یک هش SHA-256 ذخیره می‌شود؛ اگر کسی بعداً نتیجه را در دیتابیس دستکاری کند، هش دیگر نمی‌خواند
- **جلوگیری از دستکاری مبلغ:** مبلغ تأیید پرداخت همیشه از دیتابیس سرور خوانده می‌شود، نه از پارامتر ارسالی مرورگر
- **کنترل دسترسی:** هیچ کاربری نمی‌تواند قسط کاربر دیگری را پرداخت یا تأیید کند (تست خودکار دارد)
- **قفل همزمانی:** هنگام رزرو، ردیف طرح قفل می‌شود تا با رزرو همزمان چند نفر، ظرفیت از حد مجاز عبور نکند
- **گزارش رویدادها:** غیرقابل ویرایش و حذف، حتی از پنل مدیریت
- **کوکی‌های امن:** `HttpOnly`، `SameSite`، و `Secure` در حالت تولید
- **اجرا با کاربر غیر root** در داکر

### چک‌لیست پیش از راه‌اندازی واقعی

- [ ] `DJANGO_DEBUG=false` باشد
- [ ] `SECRET_KEY` تصادفی و یکتا باشد و در گیت نباشد
- [ ] `ALLOWED_HOSTS` فقط دامنهٔ خودتان باشد
- [ ] HTTPS فعال باشد (بدون آن رمزها روی شبکه قابل شنود است)
- [ ] برای حساب مدیر حتماً **2FA فعال** شود
- [ ] از PostgreSQL استفاده کنید، نه SQLite
- [ ] **پشتیبان‌گیری خودکار روزانه** از دیتابیس تنظیم شود
- [ ] `python manage.py check --deploy` را اجرا و هشدارها را برطرف کنید

> نکته دربارهٔ محدودسازی نرخ: بک‌اند پیش‌فرض کش، حافظهٔ داخلی همان پردازش است. اگر برنامه را با چند worker اجرا می‌کنید، یک بک‌اند مشترک مثل Redis در `CACHES` تنظیم کنید تا شمارش بین پردازش‌ها یکسان بماند.

## استقرار روی سرور

### با Docker (ساده‌ترین راه)

```bash
cp .env.example .env
# .env را ویرایش کنید: SECRET_KEY، DJANGO_DEBUG=false، ALLOWED_HOSTS
docker compose up -d --build
docker compose exec web python manage.py createsuperuser
```

`docker-compose.yml` شامل PostgreSQL است و پورت دیتابیس به بیرون باز نمی‌شود.

### بدون Docker

```bash
pip install -r requirements.txt
python manage.py migrate
python manage.py collectstatic --noinput
gunicorn config.wsgi:application --bind 0.0.0.0:8000 --workers 3
```

سپس nginx را به‌عنوان reverse proxy با گواهی SSL (مثلاً Let's Encrypt) جلوی آن قرار دهید.

## تست‌ها

```bash
python manage.py test
```

۳۳ تست خودکار پوشش می‌دهند: ثبت‌نام و اعتبارسنجی رمز، ورود، دومرحله‌ای، محدودسازی نرخ، رزرو و ظرفیت، ساخت اقساط، قوانین قرعه‌کشی (عدم برد دوباره، حذف افراد بدهکار)، و کنترل دسترسی بین کاربران.

هنگام اجرا ممکن است چند Traceback با عنوان `PermissionDenied` ببینید — این‌ها خطا نیستند، بلکه همان تست‌های امنیتی هستند که عمداً بررسی می‌کنند دسترسی غیرمجاز رد می‌شود.

## شخصی‌سازی

| می‌خواهید چه چیزی را عوض کنید | کجا |
|---|---|
| رنگ‌ها، فونت، ظاهر | `static/css/style.css` (بالای فایل، بخش `:root`) |
| نام و لوگوی برنامه | `templates/base.html` و `config/urls.py` |
| متن صفحات | پوشهٔ `templates/` |
| قوانین قرعه‌کشی | `loans/services.py` تابع `run_lottery_draw` |
| نحوهٔ ساخت اقساط | `loans/services.py` تابع `start_loan_plan` |
| افزودن درگاه پرداخت | `payments/gateways.py` |
| فیلدهای کاربر | `accounts/models.py` (پس از تغییر، `makemigrations` بزنید) |

### ایده‌هایی برای توسعه

اگر می‌خواهید محصول را کامل‌تر کنید: پیامک اطلاع‌رسانی سررسید و اعلام برنده، خروجی اکسل از اقساط، پشتیبانی از چند صندوق مستقل روی یک نصب (multi-tenant)، اپ موبایل با API، و صفحهٔ گزارش مالی برای مدیر.

## نکات حقوقی

پیش از استفادهٔ عمومی یا فروش، این موارد را جدی بگیرید:

**مجوز فعالیت.** جمع‌آوری پول از عموم و توزیع آن، در بسیاری از کشورها از جمله ایران، فعالیت مالی محسوب می‌شود و ممکن است نیازمند مجوز از بانک مرکزی یا نهاد ناظر باشد. صندوق خانوادگی و دوستانه معمولاً مشکلی ندارد، اما صندوقی که برای عموم باز باشد وضعیت متفاوتی دارد. پیش از راه‌اندازی عمومی با یک وکیل مشورت کنید.

**قرعه‌کشی.** در برخی حوزه‌های قضایی، قرعه‌کشی پولی مقررات خاص خود را دارد. اینکه شرکت‌کننده در نهایت پول خود را پس می‌گیرد (و این قمار نیست) معمولاً وضعیت را متفاوت می‌کند، ولی این را باید برای قوانین محل خودتان بررسی کنید.

**دادهٔ شخصی.** شما نام، شمارهٔ موبایل و احتمالاً کد ملی کاربران را نگهداری می‌کنید. مسئولیت حفاظت از این داده‌ها با شماست: پشتیبان‌گیری امن، دسترسی محدود، و حذف داده در صورت درخواست کاربر.

**اگر برنامه را می‌فروشید.** روشن کنید که خریدار مسئول اخذ مجوزها و رعایت قوانین محل خودش است. یک قرارداد ساده با یک وکیل تنظیم کنید که مسئولیت شما را نسبت به نحوهٔ استفادهٔ خریدار محدود کند.

**درگاه پرداخت.** برای فعال‌سازی درگاه واقعی به مجوز کسب‌وکار و قرارداد با شرکت پرداخت نیاز دارید. این جدا از خود برنامه است.

این توضیحات، مشاورهٔ حقوقی نیست — صرفاً فهرستی از مواردی است که باید دربارهٔ آن‌ها از یک متخصص بپرسید.
